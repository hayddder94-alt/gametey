# متجر شركة المؤمل الإلكتروني 🏬

متجر إلكتروني إنتاجي متكامل لشركة **المؤمل** — النجف الأشرف (كهربائيات، أثاث، ومنزلية — نقدًا أو بالتقسيط).

- متجر مفتوح للعملاء **بدون تسجيل دخول أو حسابات**.
- سلة تسوق محفوظة في Local Storage لا تضيع عند التحديث.
- دفع نقدي أو بالتقسيط مع حساب أسعار حقيقي **في الخادم فقط**.
- إنشاء الطلب في قاعدة بيانات SQLite حقيقية ثم إرسال رسالة منظمة إلى واتساب الشركة.
- لوحة إدارة محمية بثلاثة حسابات فقط (RBAC حقيقي على مستوى الـ API) مع سجل عمليات كامل.

## التشغيل

```bash
npm install
npm start          # http://localhost:3000
```

عند أول تشغيل يُنشئ النظام تلقائيًا:
- قاعدة البيانات في `data/almuammal.db`.
- الحسابات الإدارية الثلاثة (انظر أدناه).
- كتالوجًا أوليًا: 6 تصنيفات و15 منتجًا بخيارات وأسعار وتقسيط.

## الحسابات الإدارية (3 فقط — لا يمكن إنشاء رابع)

ثلاثة حسابات تابعة للشركة بدور موحّد `ADMIN` — جميعها بنفس الصلاحيات الكاملة لإدارة المتجر
(منتجات، أسعار، تقسيط، طلبات، عملاء، إعدادات، تقارير وسجل عمليات).

| المستخدم | كلمة المرور |
|---|---|
| `admin1` | تُولَّد عشوائيًا عند أول تشغيل |
| `admin2` | تُولَّد عشوائيًا عند أول تشغيل |
| `admin3` | تُولَّد عشوائيًا عند أول تشغيل |

- عند أول تشغيل تُكتب كلمات المرور في `data/first-run-credentials.txt` (خارج Git) وتُطبع في سجل الخادم.
- يمكن تمريرها عبر متغيرات البيئة `SEED_ADMIN1_PASSWORD` وغيرها.
- غيّرها بعد أول دخول من: الحسابات الإدارية (تعديل بيانات/تغيير كلمة مرور).
- مفروض في Backend وقاعدة البيانات: `MAX_ADMIN_USERS = 3` + Trigger يمنع الحساب الرابع، ولا يمكن تعطيل آخر حساب نشط.

الدخول من `/admin/login` (غير مذكور في قوائم المتجر).

## حالات الطلب

`NEW` طلب جديد → `PENDING_CONFIRMATION` بانتظار التأكيد → `CONFIRMED` تم التأكيد →
`PROCESSING` قيد التنفيذ → `READY` جاهز → `DELIVERED` تم التوصيل → `COMPLETED` مكتمل، أو `CANCELLED` ملغي.

المبيعات في لوحة التحكم تُحسب من الطلبات **المكتملة** فقط (ويمكن ضم «تم التوصيل» من إعدادات الشركة).

## بنية المشروع

```
server.js               نقطة الدخول (Express)
src/
  config.js             الإعدادات + MAX_ADMIN_USERS = 3 + حالات الطلب + الصلاحيات
  db.js                 SQLite (الأفضلية WAL) + الجداول + audit()
  auth.js               JWT + bcrypt + RBAC (requirePermission) + قفل محاولات الدخول
  pricing.js            محرك الأسعار (الخادم فقط): منتج + خيارات + كمية + دفع + رسوم − خصم
  orders.js             إنشاء الطلب (معاملة واحدة)، تغيير الحالة مع سجل التاريخ
  whatsapp.js           بناء رسالة واتساب الديناميكية + رابط wa.me
  upload.js             رفع الصور مع فحص نوع الملف الفعلي (magic bytes) + تحسين sharp
  seed.js               البذر الأولي (تصنيفات/منتجات/خيارات/أسعار)
  routes/               واجهات المتجر + API العامة + صفحات الإدارة + API الإدارة
views/                  قوالب EJS (RTL) للمتجر ولوحة الإدارة
public/css|js|img       الواجهة والتصميم والصور
data/almuammal.db       قاعدة البيانات (خارج Git)
```

## تدفق الطلب (نهاية إلى نهاية)

1. العميل يتصفح بدون حساب → يختار منتجًا ويحدد خياراته (لون/حجم/نص...) وطريقة الدفع.
2. السلة تُحفظ في Local Storage، والأسعار تُعاد حسابها من الخادم عبر `POST /api/cart/quote`.
3. مراجعة الطلب → إدخال بيانات العميل (تحقق: اسم، هاتف عراقي، محافظة، منطقة...).
4. `POST /api/orders` يعيد حساب الأسعار **من قاعدة البيانات فقط** (أي سعر مرسل من المتصفح يُتجاهل)،
   ينشئ رقم طلب فريد `AM-YYMMDD-XXXX` ويحفظه بحالة `PENDING_CONFIRMATION`.
5. صفحة النجاح تجهّز الرسالة من الخادم (`GET /api/orders/:num/whatsapp-message?phone=...` —
   يتطلب هاتفًا مطابقًا لمنع التطفل) وتفتح `https://wa.me/9647821296460?text=...`.
6. `POST .../whatsapp-sent` يحوّل الحالة إلى `SENT_TO_WHATSAPP`.
7. الإدارة تتابع: تغيير الحالات (مع حفظ من/قبل/بعد/الوقت)، ملاحظات داخلية، تواصل واتساب مع العميل.

## الأمان

- كلمات مرور bcrypt (10 جولات)، جلسات JWT في كوكي httpOnly (صلاحياتها من التوكن وليس الواجهة).
- RBAC عبر وسيط `requirePermission` على كل مسار إدارة — الاستدعاء اليدوي للـ API ممنوع أيضًا.
- حد محاولات دخول (8 محاولات / 15 دقيقة لكل IP) وحد لإنشاء الطلبات.
- رفع الصور: قائمة بيضاء للأنواع + فحص magic bytes + حد 6MB + أسماء عشوائية + تحويل webp عبر sharp.
- رؤوس أمان أساسية (nosniff / SAMEORIGIN / Referrer-Policy).
- تحقق من كل المدخلات (اسم/هاتف/محافظة/رابط موقع) في الخادم.

## إعدادات الشركة

تُدار من `/admin/settings` (المدير الرئيسي فقط) وتظهر في الواجهة ورسائل واتساب:
`COMPANY_NAME` • `COMPANY_PHONE=07830020117` • `WHATSAPP_COMPANY_NUMBER=9647821296460` • `COMPANY_ADDRESS=النجف - حي الكرامة، Najaf, Iraq`

## ملاحظات إنتاجية

- فعّل `HTTPS` و`JWT_SECRET` قويًا عبر متغيرات البيئة، و`secure: true` للكوكي خلف HTTPS.
- قاعدة البيانات SQLite مناسبة لحجم الطلبات المتوقع؛ يمكن الترحيل إلى PostgreSQL بنفس البنية لاحقًا.

## توثيق تسجيل الدخول عبر Supabase (مدمج وجاهز للتفعيل)

المشروع يوثّق دخول الإدارة عبر **Supabase Auth** رسميًا عند تفعيله، وبالتحقق المحلي الآمن (bcrypt) بدونه:

```bash
SUPABASE_URL=https://xxxx.supabase.co \
SUPABASE_ANON_KEY=... \
SUPABASE_SERVICE_ROLE_KEY=... \
npm start
```

عند أول تشغيل تُنشأ الحسابات الثلاثة في Supabase Auth تلقائيًا، ويظهر `via: supabase` في استجابة الدخول.
التفاصيل وخيار الاستضافة الذاتية عبر Docker في [docs/supabase-setup.md](docs/supabase-setup.md).

## التصميم (مطبَّق وفق منهجية ui-ux-pro-max)

نظام التصميم مبني على توصيات مهارة UI/UX Pro Max لنمط **Trust & Authority + Conversion**:
- نمط بصري سويسري نظيف: كحلي ثقة + ذهبي مميز، تباين نصوص ≥ 4.5:1.
- خط عربي مؤسساتي مقروء: **IBM Plex Sans Arabic**.
- **أيقونات SVG موحّدة** (`public/img/icons.svg` + دالة `icon()`) — بلا إيموجي في الواجهات.
- أهداف لمس ≥ 44px، حالات hover بانتقالات 220ms، حلقات تركيز واضحة للوحة المفاتيح.
- احترام `prefers-reduced-motion`، وتحميل كسول للصور مع أبعاد محجوزة (CLS منخفض).
